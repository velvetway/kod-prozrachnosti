# Мониторинг ценовых рисков в закупках строительных материалов

Прототип для хакатона «Код прозрачности». Специалист загружает смету или спецификацию, система
сопоставляет каждую позицию с ресурсом классификатора и сверяет её с обоснованными ориентирами:

* **цена** — с медианой трёх источников (сметная цена ФГИС ЦС, контракты-аналоги ЕИС, рыночные
  предложения), приведённых к кварталу проверки индексом цен, с учётом региона и ценовой зоны;
* **объём** — расход материала на 1 м² объекта против коридора объектов-аналогов;
* **удорожание** — заявленный рост цены против индекса цен группы ресурсов за тот же период.

По каждой позиции выдаётся воспроизводимый расчёт: источник, квартал, индекс, формула, сумма.
Специалист фиксирует решение в журнале, отчёт выгружается в DOCX.

> **Данные.** В репозитории лежат **демонстрационные** справочники для Брянской и Томской областей
> (`data/reference/demo`, генератор `tools/make_demo_data.py`). Цены, контракты, прайс-листы и
> объекты-аналоги в них синтетические и помечены «демо» во всех экранах и отчётах. В базу внесены все
> 89 субъектов РФ; реальные выгрузки загружаются в разделе «Справочники цен» в формате CSV (ниже).

## Запуск

### Docker (одна команда)

```bash
docker compose up --build
```

Открыть http://localhost:8000. Поднимаются PostgreSQL 16 и приложение; при первом старте база
заполняется 89 регионами и демо-справочниками.

### Без Docker (SQLite)

Нужны Python 3.12+ и Node.js 20+.

```bash
pip install -r backend/requirements.txt
cd frontend && npm ci && npm run build && cd ..   # если папки frontend/dist ещё нет
cd backend && uvicorn app.main:app --port 8000
```

Открыть http://localhost:8000. База — файл `data/app.db` (удалите его, чтобы начать с чистого листа).
Для PostgreSQL задайте `DATABASE_URL=postgresql+psycopg://user:pass@host:5432/db`.

Режим разработки интерфейса: сервер как выше, затем `cd frontend && npm run dev` →
http://localhost:5173 (запросы `/api` проксируются на порт 8000).

## Демонстрационный сценарий

На странице «Новая проверка» раскройте «Демо-сметы с заранее известными отклонениями» и нажмите
«Подставить» — файл и параметры объекта заполнятся сами.

| Смета | Что должна показать система |
|---|---|
| `01_bryansk_school_smeta.xlsx` — капремонт школы, Брянская обл., III кв. 2026, 4 200 м² | бетон B25 +33 % (высокий), минвата +22 % и окна +17 % (средние), линолеум — перерасход ≈ +62 % на 1 м², арматура в кг пересчитана в тонны, бетон В15 с низкой сопоставимостью → «проверить сопоставление», фасадные панели — нет ориентира (подбор вручную) |
| `02_tomsk_polyclinic_spec.xlsx` — поликлиника, Томская обл., зона 2 (северные районы) | цены выше, чем в Томске, но в пределах ориентира своей зоны — сигналов по цене нет; удорожание кабеля +38 % при индексе +7 % (высокий) и окон +22 % при +4 % (средний). Если выбрать зону 1, все позиции получат ложные сигналы |
| `03_bryansk_road_smeta.xlsx` — благоустройство, II кв. 2026 | сигналов нет |

Ожидаемые результаты записаны в `demo/expected.json` и проверяются автотестами.

## Как считается

* **Сопоставление.** Совпадение кода КСР → сопоставимость 1,0. Иначе нечёткое сравнение наименований
  (rapidfuzz) среди ресурсов с совместимой единицей, с приведением латиницы и кириллицы (B25 = В25) и
  проверкой числовых характеристик (класс, диаметр, марка). Уровни: ≥ 0,90 высокая, ≥ 0,75 средняя,
  ≥ 0,60 низкая, ниже — «нет ориентира». При низкой сопоставимости сигнал получает статус «проверить
  сопоставление». Специалист может сопоставить позицию вручную.
* **Ориентир цены** = медиана значений источников; значение ЕИС и рынка — медиана их записей; каждая
  запись приводится к кварталу проверки: `цена × индекс(квартал проверки) / индекс(квартал записи)`.
* **Отклонение цены** = `(цена за ед. ресурса − ориентир) / ориентир × 100 %`; превышение =
  `(цена − ориентир) × количество`.
* **Объём**: `расход на 1 м² = количество / мощность`; сравнение с медианой объектов-аналогов того же
  типа в регионе (если их меньше трёх — во всех регионах).
* **Удорожание сверх индекса** = `(новая цена / исходная цена) / индекс за период − 1`.
* Пороги по умолчанию (средний / высокий): цена 15 / 30 %, объём 25 / 50 %, удорожание 10 / 20 %;
  меняются в форме проверки и записываются в отчёт.
* **Воспроизводимость.** Расчёт — правила и статистика без случайных величин; порядок кандидатов
  фиксирован. В проверку записываются контрольная сумма файла, версии справочников и контрольная
  сумма результата; кнопка «Повторить расчёт» показывает, что она совпала.

## Формат справочников (CSV, UTF-8, разделитель `,` или `;`)

| Вид | Колонки |
|---|---|
| Цены | `source` (fgiscs, eis, market), `ksr_code`, `region`, `zone`, `quarter` (2026-Q3), `price`, `doc_ref`, `doc_url`; для нового ресурса — `name`, `unit`, `group` |
| Индексы | `region`, `group`, `quarter`, `value` |
| Объекты-аналоги | `region`, `object_type`, `name`, `capacity`, `ksr_code`, `consumption_per_m2`, `doc_ref` |
| Ресурсы | `ksr_code`, `name`, `unit`, `group`, `attributes` |

Каждая загрузка — новая версия набора данных (код, SHA-256, число записей).

Смета: XLSX или CSV с колонками «Наименование», «Ед. изм.», «Количество», «Цена»; по желанию «Код КСР»
и «Исходная цена» (для проверки удорожания). Строку заголовка система находит сама, строки
«Итого», разделов и без чисел пропускает с предупреждением.

## Структура

```
backend/app/
  core/parser.py     извлечение позиций из XLSX/CSV
  core/units.py      единицы измерения и пересчёт
  core/matching.py   сопоставление с классификатором
  core/calc.py       ориентиры, индексация, коридор аналогов
  core/pipeline.py   конвейер проверки, сигналы, контрольная сумма
  reference/         89 регионов, загрузка справочников
  report.py          отчёт DOCX
  main.py            HTTP API (документация: http://localhost:8000/docs)
frontend/src/        интерфейс (React): реестр, новая проверка, результаты, карточка сигнала,
                     справочники, объекты-аналоги, журнал решений
data/reference/demo/ демо-справочники
demo/                демо-сметы и ожидаемые результаты
tools/               генераторы демо-данных
```

## Тесты

```bash
pip install -r backend/requirements-dev.txt
cd backend && python -m pytest -q
```

26 тестов: единицы и сопоставление, ожидаемые сигналы на демо-сметах, влияние ценовой зоны,
воспроизводимость (одинаковый вход → одинаковая контрольная сумма, повторный расчёт сохраняет
решения), API, отчёт, отказ на некорректных файлах.

## Ограничения прототипа

* Справочники демонстрационные; подключение к ФГИС ЦС и ЕИС — через загрузку выгрузок CSV, без
  автоматического обмена.
* XML локального сметного расчёта (схема Минстроя) не разбирается — нужен XLSX или CSV.
* Сопоставление наименований — нечёткое сравнение строк; семантический поиск на локальной модели
  эмбеддингов в эту версию не вошёл.
* Нет авторизации и разграничения ролей: один демо-пользователь.
* Не проверяются подлинность коммерческих предложений, аффилированность и дробление закупок.
* Сигнал — повод для проверки, а не вывод о нарушении.

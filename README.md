# Мониторинг ценовых рисков в закупках строительных материалов

Прототип для хакатона «Код прозрачности». Специалист по профилактике коррупционных правонарушений
загружает смету или спецификацию. Система сопоставляет каждую позицию с ресурсом классификатора
строительных ресурсов (КСР) и сверяет её с обоснованными ориентирами:

* **цена** — с медианой источников: сметная цена ФГИС ЦС, контракты-аналоги ЕИС, рыночные
  предложения. Все значения приводятся к кварталу проверки индексом, рассчитанным по динамике
  сметных цен ФГИС ЦС;
* **объём** — расход материала на 1 м² объекта против объектов-аналогов того же типа;
* **удорожание** — рост цены относительно исходной против индекса за тот же период.

Каждый сигнал объясним: источник, квартал, индекс, формула, сумма. Решение принимает специалист и
фиксирует его в журнале; отчёт выгружается в DOCX.

## Данные

| Набор | Тип |
|---|---|
| Сметные цены ФГИС ЦС: 13 157 цен, 2 944 ресурса КСР, Брянская и Томская области, IV кв. 2024 — III кв. 2026 | **реальные**, с портала fgiscs.minstroyrf.ru |
| Контракты-аналоги ЕИС, рыночные предложения, объекты-аналоги | синтетические, помечены «СИНТ-» |
| Демо-сметы (3 документа, 25 позиций) | синтетические документы на реальных ресурсах КСР |
| Субъекты РФ | все 89 |

Источник, правовой статус, объём и пропуски каждого набора описаны в [`docs/DATA.md`](docs/DATA.md).
Чтобы получить результат только по реальным данным, в форме проверки оставьте один источник — ФГИС ЦС.

## Запуск

Требования: Docker с Compose v2, **или** Python 3.12+ (без Docker). Node.js 20+ нужен только для
пересборки интерфейса.

### Docker

```bash
docker compose up --build
```

Открыть http://localhost:8000. Поднимаются PostgreSQL 16 и приложение. При первом старте база
заполняется 89 регионами, сметными ценами ФГИС ЦС и демо-справочниками (около 5 секунд).

### Без Docker (SQLite)

```bash
pip install -r backend/requirements.txt
cd frontend && npm ci && npm run build && cd ..   # только если нет папки frontend/dist
cd backend && uvicorn app.main:app --port 8000
```

Открыть http://localhost:8000. База — файл `data/app.db`; удалите его, чтобы начать с чистого листа.
Для PostgreSQL задайте `DATABASE_URL=postgresql+psycopg://user:pass@host:5432/db`.

### Вход

| Логин / пароль | Роль | Может |
|---|---|---|
| `specialist` / `specialist` | специалист | проверять документы, сопоставлять вручную, принимать решения |
| `admin` / `admin` | администратор справочников | то же, плюс загрузка справочников и журнал аудита |

Учётные записи задаются переменной `APP_USERS` («логин:пароль:Имя:роль,…») при первом запуске; пароли
хранятся как хеш PBKDF2. Для рабочей установки задайте свои пароли.

Режим разработки интерфейса: сервер как выше, затем `cd frontend && npm run dev` →
http://localhost:5173 (запросы `/api` проксируются на порт 8000).

## Демонстрационный сценарий

Войдите как `specialist`. На странице «Новая проверка» раскройте «Демо-сметы» и нажмите «Подставить»:
файл и параметры объекта заполнятся сами. Затем нажмите «Запустить проверку».

| Документ | Что покажет система |
|---|---|
| `01_bryansk_school_smeta.xlsx` — капремонт школы, Брянская обл., III кв. 2026, 4 200 м² | бетонная смесь B20 +33 % к сметной цене ФГИС ЦС (высокий); минвата +22 % и дверные блоки +20 % (средние); керамогранит — перерасход +57 % на 1 м²; арматура указана в кг без кода — найдена и пересчитана в тонны; бетон В7,5 с низкой сопоставимостью → «проверить сопоставление»; фасадные панели — нет аналога в КСР (подбор вручную) |
| `02_tomsk_polyclinic_spec.xlsx` — поликлиника, Томская обл., изменение цены контракта от III кв. 2025 | цены в пределах ориентира; кабель АВВГнг(A)-LS подорожал на 42,7 % при индексе +10,6 % (высокий); сэндвич-панель +25,9 % при +7,6 % (средний) |
| `03_bryansk_road_smeta.xlsx` — благоустройство, II кв. 2026 | сигналов нет |

Дальше: откройте карточку сигнала, посмотрите источники и формулу, запишите решение, скачайте отчёт,
нажмите «Повторить расчёт» — контрольная сумма совпадёт.

## Как считается

* **Сопоставление.** Совпал код КСР → сопоставимость 1,0. Иначе позиция сравнивается с ресурсами,
  у которых есть цена в регионе: нечёткое сравнение наименований (rapidfuzz) среди ресурсов с
  совместимой единицей. Латиница и кириллица приводятся к одной записи (B25 = В25), числовые
  характеристики (класс, диаметр, марка, толщина) сверяются отдельно. Уровни: ≥ 0,90 высокая,
  ≥ 0,75 средняя, ≥ 0,60 низкая, ниже — «нет ориентира». При низкой сопоставимости сигнал получает
  статус «проверить сопоставление».
* **Индекс между кварталами** — медиана отношений сметных цен ФГИС ЦС одних и тех же ресурсов
  раздела КСР. Если общих ресурсов в разделе меньше трёх, берётся книга КСР, затем все материалы
  региона. Загруженный официальный индекс имеет приоритет.
* **Ориентир цены** = медиана значений источников. Значения ЕИС и рынка — медианы их записей,
  каждая приведена к кварталу проверки.
* **Отклонение** = `(цена за ед. ресурса − ориентир) / ориентир × 100 %`; превышение =
  `(цена − ориентир) × количество`.
* **Объём**: `расход на 1 м² = количество / мощность`, сравнение с медианой объектов-аналогов.
* **Удорожание сверх индекса** = `(новая цена / исходная цена) / индекс за период − 1`.
* **Пороги по умолчанию** (средний / высокий): цена 15 / 30 %, объём 25 / 50 %, удорожание 10 / 20 %.
  Пороги меняются в форме проверки и записываются в отчёт.
* **Воспроизводимость.** Расчёт выполняется правилами и статистикой без случайных величин, порядок
  кандидатов фиксирован. В проверку записываются SHA-256 файла, версии справочников и SHA-256
  результата.

## Проверка качества

```bash
pip install -r backend/requirements-dev.txt
cd backend && python -m pytest -q          # 29 автотестов
cd .. && python tools/evaluate.py           # метрики на тестовом наборе → docs/test_results.md
```

Результаты: [`docs/test_results.md`](docs/test_results.md). На тестовом наборе извлечено 25 из 25
позиций, сопоставлено с нужным ресурсом 24 из 24, выявлено 7 из 7 ожидаемых сигналов, лишних нет,
повторный расчёт совпал 3 из 3. Набор мал и составлен командой — это проверка логики, а не оценка
точности на реальных сметах.

## Обновление данных

```bash
python tools/fetch_fgiscs.py        # новая выгрузка сметных цен с портала ФГИС ЦС
python tools/make_demo_data.py      # синтетические ЕИС, рынок, объекты-аналоги
python tools/make_demo_files.py     # демо-сметы и ожидаемые результаты
```

Справочники загружаются при первом запуске на пустой базе. После обновления удалите `data/app.db`
(или том `pgdata` в Docker). Реальные выгрузки ЕИС и прайс-листов загружаются CSV-файлом в разделе
«Справочники цен» (роль «администратор»); форматы колонок указаны на той же странице и в `docs/DATA.md`.

## Ограничения прототипа

* Реальные только сметные цены ФГИС ЦС двух регионов; ЕИС, рынок и объекты-аналоги синтетические.
  Выводы, которые от них зависят, не являются подтверждёнными.
* Портал публикует для региона не все ресурсы КСР; если цены за квартал нет, берётся соседний квартал
  с пересчётом.
* XML локального сметного расчёта (схема Минстроя) не разбирается — нужен XLSX или CSV.
* Сопоставление по наименованию — нечёткое сравнение строк, без семантической модели. Возможны
  ошибки на сильно переформулированных наименованиях; для этого есть показатель сопоставимости и
  ручной подбор.
* Сервер работает по HTTP. В рабочей установке TLS включается на обратном прокси (nginx), а
  стандартные пароли заменяются.
* Не проверяются подлинность коммерческих предложений, аффилированность и дробление закупок.
* Сигнал — повод для проверки, а не вывод о нарушении.
